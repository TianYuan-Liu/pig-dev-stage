Methods
Data acquisition and stage annotation
Bulk RNA-seq transcript-per-million (TPM) matrices and accompanying sample metadata were obtained from the pigGTEx resource (machine_learning/data_processing/data_loader.py). For each target tissue, gzip-compressed TPM matrices (`*.expr_tpm.txt.gz`) were read alongside the global metadata table (`data/full_metadata.csv`). Ages recorded in days were harmonised to developmental stages using fixed cut-offs (Infant: 0-20 d, Early childhood: 21-59 d, Pre-pubertal: 60-149 d, Post-pubertal: 150-365 d, Adult: >365 d). The loader aligns sample identifiers between expression and metadata tables, falling back to positional matching only when identifier formats differ, and retains sex information with an explicit "Unknown" category. Prior to modelling, genes must exceed 0.1 TPM in at least 10% of samples, ensuring sufficient detection across the tissue cohort.

Tissue eligibility and adaptive stage granularity
To balance class resolution with available sample sizes, an adaptive StageGranularitySelector (machine_learning/data_processing/stage_selection.py) evaluated per-tissue stage counts. Tissues qualified for the most granular scheme that satisfied predefined thresholds: >=40 samples per class after merging Adult into Post-pubertal for the 4-class schema, >=30 per class for the 3-class schema that combines early childhood stages, and >=25 samples per dichotomised class with >=60 annotated samples overall for the 2-class schema. Stages are remapped according to the selected schema, guaranteeing ordered labels for downstream ordinal analyses while preserving the original biological ordering.

Pre-processing
Expression matrices were transformed using the ExpressionPreprocessor (machine_learning/data_processing/preprocessing.py). The module applies log2(TPM+1) scaling, removes genes below the 20th percentile of variance within the tissue, and standardises each retained gene to zero mean and unit variance. Although the preprocessor can regress out user-specified covariates through gene-wise linear models, the default pipeline runs without covariate removal while preserving the hooks for future adjustments. Quality-control logging (machine_learning/run_pipeline.py) flags missing values, zero-variance genes, outlier sample means (>3 standard deviations), and metadata mismatches before modelling proceeds.

Feature selection
For tissue-specific models, dimensionality is reduced with a FastFeatureSelector (machine_learning/feature_engineering/fast_feature_selection.py) configured to rank genes by mutual information with the target labels after reiterating the 20th-percentile variance screen. Up to 2,000 genes (or all available features when fewer pass filtering) are retained, with selection seeded at 42 and parallelised across all CPU cores. Selected gene sets are recorded and the leading 50 markers per tissue are exported with the model outputs. Cross-tissue analyses replace this fast selector with a stability-focused Elastic Net selector (StableFeatureSelector) to obtain reproducible gene sets across folds.

Model training
Model choice is contingent on the selected stage schema. Binary problems use scikit-learn's `LogisticRegression` with class-balanced weights, solver selection adaptive to sample size (`liblinear` when <1,000 samples, otherwise `lbfgs`), and a 5,000-iteration cap to guarantee convergence. Ordinal settings employ a custom cumulative link logistic regression (OrdinalLogisticRegression) that instantiates a sequence of Elastic Net-regularised binary classifiers across adjacent thresholds while retaining ordered decision boundaries. For each tissue, data are partitioned into training and evaluation cohorts via a 70:30 split; stratification is enforced when every class has >=2 samples, otherwise the pipeline alerts the user and reverts to an unstratified split. All stochastic elements are seeded with 42 to enable reproducibility.

Performance evaluation
Evaluation uses the MetricCalculator (machine_learning/model_evaluation/evaluation.py), which consumes class predictions and posterior probabilities. Primary endpoints are balanced accuracy and macro-averaged F1 score, supplemented by weighted F1, Matthews correlation, per-class precision/recall, full confusion matrices, and AUROC/AUPRC (macro- and class-specific) when probabilistic outputs are available. For ordinal problems (>2 classes), the evaluator reports mean absolute stage error, quadratic and linear weighted Cohen's kappa, Spearman's rho, Kendall's tau, and a +/-1-stage "near miss" accuracy. Confidence intervals for balanced accuracy, macro-F1, and (when applicable) ordinal MAE are estimated via 1,000 bootstrap resamples at the 95% confidence level. All metrics and confidence intervals are serialised per tissue as JSON artefacts.

Cross-tissue generalisation analyses
When cross-tissue validation is requested, the pipeline enumerates eligible tissues from previously generated discovery outputs and reloads their expression profiles and metadata. For each tissue, data are filtered to genes shared across the cohort (requiring at least 1,000 common genes) and preprocessed with a cloned ExpressionPreprocessor. A StableFeatureSelector (Elastic Net logistic regression with variance filtering) is fit on the pooled training tissues to obtain a consensus feature space. A cloned logistic regression model is then trained on the union of all but one tissue and evaluated on the held-out tissue in a leave-one-tissue-out (LOTO) framework, yielding balanced accuracy and macro-F1 for each held-out tissue. Within-tissue baselines, produced via stratified 80:20 splits, provide context for generalisation gaps, and optional analyses compute pairwise tissue similarity matrices and low-dimensional embeddings (PCA or UMAP) of the cross-tissue expression landscape. All cross-tissue metrics, transfer matrices, and gap estimates are written to `machine_learning/model_outputs/`.

Implementation details
The orchestrator (`machine_learning/run_pipeline.py`) manages per-tissue execution, enhanced logging, and progress tracking. PerformanceLogger hooks record wall-clock and peak memory for every pipeline phase, while the PipelineProgressTracker maintains resumable progress metadata in `machine_learning/timing_history.json`. Results for each tissue, including configuration, quality-control notes, selected gene lists, and performance summaries, are saved as human-readable JSON files, and an aggregate `pipeline_summary.json` captures run-level metadata. The pipeline therefore delivers fully reproducible, audit-trailed analyses that can be executed tissue-by-tissue or en masse for downstream reporting and manuscript preparation.
